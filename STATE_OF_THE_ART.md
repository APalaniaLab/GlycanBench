# GlycanBench: Tool-by-Tool State-of-the-Art Comparison

Each row corresponds to one entry in the application menu (as defined in `NavBar.tsx` and routed in `App.tsx`). The **State of the Art** column describes what the field currently offers for that task. The **Our Contribution** column describes what GlycanBench implements, verified against the actual source code, including precise algorithmic and UX details.

---

## CREATE

| Tool | State of the Art | Our Contribution |
|------|-----------------|-----------------|
| **Glycan Molecule** (`/GlycanMolecule`) | Standard cheminformatics pipelines generate 3D conformers from SMILES using RDKit's distance-geometry algorithm (ETKDG) followed by MMFF94 or UFF force-field minimization. Tools such as OpenBabel and Avogadro expose this capability locally. Carbohydrate-specific force fields (GLYCAM06, GROMOS 56A6CARBO) are the gold standard for conformational accuracy but require expert setup, local installation, and are not web-accessible for arbitrary inputs. GLYCAM-Web covers only a fixed library of pre-computed structures. | GlycanBench provides a **visual click-to-build glycan constructor** in the browser: users assemble sequences by clicking sugar tokens (60+ monosaccharides), linkage tokens, and branching brackets `[` `]` from validated button palettes. Structural grammar is enforced in real time (a bond must follow a sugar; a sugar must follow a bond or bracket). On submission, the built sequence is sent to three simultaneous backend calls: (1) `POST /api/draw` — SNFG 2D rendering via `GlycoDraw`; (2) `POST /api/convert` — format conversion to IUPAC, SMILES, GlycoCT, WURCS; (3) `POST /api/visualize` — IUPAC canonicalization via `glycowork`, SMILES via `IUPAC_to_SMILES()`, **ETKDGv3** 3D embedding (chirality enforcement, small-ring torsion corrections), minimized with **MMFF94s** (static variant, better for cyclic systems) with UFF fallback, MDL Molfile returned and rendered in **3Dmol.js** with four switchable display styles (Ball & Stick, Spacefill/CPK, Wireframe, Stick Figure) and screenshot export. The integration of a guided sequence builder, simultaneous 2D/3D/format output, and a tiered ETKDGv3 + MMFF94s + UFF optimization pipeline in a browser-native 3D viewer is not available in any existing glycomics web tool. |
| **Biosynthetic Networks** (`/BiosyntheticNetworks`) | `glycowork` (Thomès et al., 2021–2024) introduced programmatic biosynthetic network construction from sets of IUPAC-condensed glycans using curated enzymatic rules. GlyConnect and GlyTouCan maintain curated biosynthetic data as static databases. No web application exposes interactive, fully parameterized biosynthetic network construction from arbitrary user-supplied glycan sets. | GlycanBench wraps `glycowork.network.biosynthesis.construct_network()` in a REST API and an interactive Cytoscape.js frontend. Users control three orthogonal parameters: (1) **edge type** (`monolink`, `full_reaction`, or `enzyme`-labeled); (2) **allowed PTMs** — dynamically fetched from `lib.ptm_dict` at startup and toggled individually (acetylation, phosphorylation, sulfation, etc.); (3) **permitted roots** — comma-separated custom reducing-end anchors (defaulting to `Gal(b1-4)GlcNAc-ol` and `Gal(b1-4)Glc-ol`). The response is a Cytoscape.js element list with `is_input` and `is_root` node flags. The frontend supports dark/light mode, debounced node search with zoom-to-result animation, node tap highlighting (selected node + neighbors + connected edges), PNG export at 2× resolution, `breadthfirst` directed layout with animated re-layout, and structured metadata (node/edge count, params used). Four curated example glycan sets (complex N-glycans, fucosylated oligosaccharides, GSL cores, sulfated/phosphorylated glycans) are provided. The combination of all three parameter axes with a live Cytoscape.js interactive graph in a web interface is not available elsewhere. |
| **Interconvert Between Formats** (`/GlycanFormatConverter`) | GlycoWorkbench and the `glypy` library support bidirectional conversion among GlycoCT, WURCS, and IUPAC. `glycowork` provides IUPAC canonicalization and IUPAC→SMILES. No single web endpoint handles all four major formats (IUPAC, GlycoCT, WURCS, SMILES) in one request while clearly reporting unsupported conversion paths. | GlycanBench accepts IUPAC-condensed, GlycoCT, or WURCS as input and returns all four representations in a single API response. The IUPAC path uses `glycowork.motif.processing.canonicalize_iupac()` + `IUPAC_to_SMILES()`. GlycoCT/WURCS paths use `glypy.io` loaders and dumpers. A known limitation — IUPAC→GlycoCT and IUPAC→WURCS — is exposed to the user with an explicit "not supported" message rather than silently failing or omitting the field. The frontend filters unsupported/failed fields from the results panel and shows them separately as orange-labeled notices. Per-format copy-to-clipboard and file download (with correct extensions: `.gct`, `.wurcs`, `.txt`) are provided. This transparent handling of partial conversion coverage, alongside syntax-highlighted collapsible result cards, is a practical UX contribution over existing command-line tools. |

## VISUALIZE

| Tool | State of the Art | Our Contribution |
|------|-----------------|-----------------|
| **2D Draw** (`/GlycanDrawer`) | The SNFG (Symbol Nomenclature for Glycans) standard (Varki et al., 2015; NIBIB 2017) is the community-adopted 2D depiction scheme. DrawGlycan-SNFG and GlycoWorkbench are reference tools. `glycowork`'s `GlycoDraw` function (Thomès et al., 2021) provides programmatic SNFG rendering with optional motif highlighting, built on Matplotlib. Most standalone tools require local installation or a Java runtime. | GlycanBench exposes `GlycoDraw(draw_this, highlight_motif)` as a REST endpoint (`POST /api/draw`). Any substring of the IUPAC string can be passed as `highlight_motif`, triggering selective color overlay on matching structural elements — a feature absent in most web-based SNFG renderers. The result is a base64-encoded PNG returned in one call, directly renderable in the browser with a download link. The "Autofill Example" button prefills a complex sialylated, fucosylated N-glycan with a Lewis-motif highlight to demonstrate the feature. This is the only web-accessible SNFG renderer providing per-motif highlighting in a single stateless request. |
| **3D Representation** (`/visualize`) | Browser-based 3D molecular viewers (3Dmol.js, NGL Viewer, Speck) are mature. GLYCAM-Web provides GLYCAM06-minimized 3D structures but only for its pre-computed library. No web service generates high-quality, on-demand 3D structures from IUPAC strings for arbitrary glycan inputs with force-field minimization optimized for ring-heavy carbohydrate systems. | GlycanBench generates a 3D conformer for any syntactically valid IUPAC input on demand (`POST /api/visualize`) using a multi-step pipeline: **ETKDGv3** (RDKit's best distance-geometry algorithm, with chirality enforcement and small-ring torsion corrections active — directly beneficial for pyranose rings) with classic ETKDG as fallback; minimization with **MMFF94s** (the static variant, better suited to cyclic systems than standard MMFF94) for up to 2000 iterations with a second pass if energy remains high; **UFF fallback** when MMFF94s cannot be set up for the molecule. The result is an MDL Molfile rendered in 3Dmol.js with a dark background, semi-transparent VDW surface overlay, four display style buttons (Ball & Stick, Spacefill, Wireframe, Stick Figure), Reset View, Save as PNG, and Clear & Reset. The absence of a pre-computed library restriction — any valid IUPAC string triggers on-demand generation — combined with the ETKDGv3 + MMFF94s + UFF tiered optimization pipeline, is the key differentiator from GLYCAM-Web and generic cheminformatics tools. |
| **KEGG Pathway View** (`/pathwayMaps`) | KEGG (Kanehisa et al.) is the gold standard for metabolic and glycan biosynthesis pathway maps. The KEGG REST API provides programmatic image access. Browser requests to `rest.kegg.jp` fail due to CORS restrictions, preventing direct client-side rendering. Most bioinformatics tools (Bioconductor's `KEGGREST`, PathVisio) consume KEGG data locally. | GlycanBench implements three backend endpoints: (1) `GET /api/pathway?kegg_id=...` — tries `rest.kegg.jp/get/{id}/image` first, falls back to the direct `kegg.jp/kegg/pathway/...` PNG URL pattern, returns the validated image URL; (2) `GET /api/search_pathways?query=...` — a fully compliant FastAPI endpoint using a `Query` parameter (min_length=3) that proxies the KEGG `find/pathway/` endpoint for autocomplete search (debounced at 300 ms client-side), returning structured `{id, name}` results with proper `HTTPException` error handling; (3) `GET /api/proxy_image?url=...` — downloads the KEGG PNG server-side and streams it as a file download, bypassing browser CORS restrictions. The frontend uses `react-zoom-pan-pinch` for interactive pan/zoom/reset of the pathway image. Ten curated example pathways (N-glycan biosynthesis, O-glycan biosynthesis, heparan sulfate, ganglio-series GSLs, glycan degradation, LPS biosynthesis, etc.) are provided as quick-access buttons. This is the only glycomics workbench embedding live KEGG pathway browsing with integrated autocomplete search and CORS-bypassed download. |

## ANALYSE

| Tool | State of the Art | Our Contribution |
|------|-----------------|-----------------|
| **Monosaccharide** (characterization, `/characterize`) | Cross-species statistical analysis of monosaccharide occurrence is available programmatically via `glycowork.motif.analysis.characterize_monosaccharide()`. Manual cross-queries across GlyTouCan, UniCarbKB, and GlycoStore are the alternative. No interactive web tool provides taxonomic-rank-stratified occurrence charts for arbitrary monosaccharides on demand with user-controlled parameters. | GlycanBench wraps `characterize_monosaccharide(sugar, rank, focus, modifications, thresh)` in a parameterized web form. Users control: monosaccharide name (free text), taxonomic rank (Kingdom through Variants/Neighbors via a dropdown), biological focus (free text, e.g. "Bacteria"), a toggle for considering chemical modifications, and a threshold slider (1–50, minimum count for inclusion). The result is a publication-quality Matplotlib bar chart returned as a base64 PNG. The form defaults to `D-Rha`, rank=Kingdom, focus=Bacteria, modifications=on, thresh=10 — a meaningful glycobiology example. The parameterized, web-accessible interface with real-time feedback is novel; the underlying statistical logic belongs to `glycowork`. |
| **Glycan** (insight, `/GlycanInsight`) | Annotation of a glycan's biological context requires manual cross-queries of GlyTouCan, UniCarbKB, GlyConnect, and the literature. `glycowork`'s `get_insight()` automates this against its internally curated database. No web tool presents all annotation axes (species, phyla, motifs, GlyTouCan ID, cell lines, diseases) in a single structured dashboard. | GlycanBench accepts either an IUPAC-condensed sequence or a bare GlyTouCan accession number (auto-detected: starts with `G`, contains no `(`). GlyTouCan IDs are resolved to IUPAC via `glytoucan_to_glycan()`. `get_class()` classifies the glycan. `get_insight()` stdout is captured and regex-parsed into six structured fields. The frontend renders results as animated dashboard cards: a Doughnut chart (Chart.js) for phyla distribution; a species tag cloud with "show more/less" toggle at 40 entries; a sortable disease table with up/down regulation color coding; a cell lines list; a motif tag cloud; and a GlyTouCan ID badge. A "no biological information found" graceful empty state distinguishes "valid glycan, no database entry" from actual errors. The structured multi-panel dashboard from a single text input is not available in any current glycomics tool. |
| **Molecule Descriptors** (`/DescriptorCalculator`) | Cheminformatics descriptor calculation is mature (RDKit, Mordred, PaDEL). For glycans specifically, no dedicated web server computes the full physicochemical descriptor set together with glycan-specific SMARTS motif counts and five fingerprint types in a unified request. `glycowork` computes glycan-specific graph descriptors but not cheminformatics fingerprints. | GlycanBench computes, from IUPAC (canonicalized via `glycowork`) or direct SMILES: **17 physicochemical descriptors** (MW, exact MW, heavy atom count, formula, total atom count, stereocenters, unspecified stereocenters, ring count, aliphatic/saturated rings, H-bond donors/acceptors, rotatable bonds, TPSA, LogP, fraction Csp3, molar refractivity); **full elemental composition** with O/N ratio; **5 glycan-specific SMARTS motif counts** (pyranose rings `[OX2r5;!R0]`, furanose rings `[OX2r4;!R0]`, N-acetyl groups `[NX3][CX3](=O)`, carboxyl groups, sulfate groups); and **5 × 2048-bit fingerprints** (Morgan R2, Morgan R3, Atom Pair, Topological Torsion, RDKit path maxPath=7). An optional second SMILES enables Tanimoto similarity across all fingerprint types in the same request. The frontend presents results in 8 color-coded, tab-filterable group cards (Molecular Weight, Ring Systems, Bonds & H-Bonding, Atom Counts, Physicochemical, Stereochemistry, Glycan Motifs, Elemental Composition) with animated entry, a Quick Stats panel, a PubChem lookup link, and CSV download. This integration of glycan-specific SMARTS counts with the full standard cheminformatics descriptor panel in one parameterized endpoint is not available elsewhere. |
| **Motif Mutation** (`/MotifMutation`) | Systematic in-silico mutagenesis of glycan sequences to study motif robustness has not been exposed as a web tool in any published glycomics platform. Glycan mutagenesis has been performed in ad hoc research code. | GlycanBench tokenizes an IUPAC string by splitting on `(` and `)` into alternating [monosaccharide, linkage] arrays, then performs stochastic positional mutagenesis with three configurable intensity modes: `normal` (exactly `n_mut` positions replaced), `moderate` (`n_mut+1`, capped at ¼ of sequence length), `extreme` (up to ½ of all positions). For each of `n` mutant sequences (configurable, default 100), all pentamer glycowords (5-token sliding windows: sugar–bond–sugar–bond–sugar, step 2) are extracted and their frequencies tallied across the full mutant ensemble. Replacement pools: monosaccharides drawn from `monosaccharides_counts.csv` (experimentally observed frequencies); bonds from a hardcoded vocabulary of 35 α/β linkages. The frontend renders the frequency distribution as a Chart.js bar chart, color-coded by intensity mode (green/yellow/red). A built-in Help modal with 5 collapsible accordion steps explains the pipeline. This is the only interactive tool offering configurable in-silico glycan mutagenesis with motif-frequency profiling for studying structural robustness. |

## COMPARE

| Tool | State of the Art | Our Contribution |
|------|-----------------|-----------------|
| **Two Glycans** (`/CompareGlycans`) | Glycan similarity metrics include tree edit distance (used in GlycoSimilarity), substructure-based overlap (GlycoMod), `glycowork` graph similarity, and fingerprint-based Tanimoto similarity. No interactive web tool reports multi-fingerprint Tanimoto comparisons simultaneously for a glycan pair with per-fingerprint hover explanations. | GlycanBench first converts both IUPAC inputs to SMILES via `POST /api/convert`, then computes `POST /api/compare_glycans` — pairwise Tanimoto similarity across any user-selected subset of five 2048-bit fingerprint types: Morgan R2 (ECFP4-equivalent), Morgan R3 (ECFP6-equivalent), Atom Pair, Topological Torsion, RDKit path (maxPath=7). A "Select All" toggle is provided. Results are displayed with the derived SMILES strings shown explicitly, and each fingerprint score is accompanied by an `IoHelpCircleSharp` hover tooltip explaining what structural features that fingerprint encodes. Presenting five fingerprint scores simultaneously enables users to assess whether similarity is consistent across fingerprint families (robust structural resemblance) or fingerprint-dependent (only specific substructures shared). This multi-fingerprint consensus view with per-fingerprint explanations is not available in any existing glycan comparison tool. |

## ALIGN

| Tool | State of the Art | Our Contribution |
|------|-----------------|-----------------|
| **Glycan Sequences** (`/sequenceAlignment`) | Pairwise alignment of glycan sequences has been approached via BLAST-like string alignment (inappropriate for branched structures), SweetAlign (2006, Smith-Waterman with simple match/mismatch scoring), and custom solutions. GLYSUM (Alocci et al., 2015, *Glycobiology*) introduced the first rigorously derived glycan substitution scoring matrix, analogous to BLOSUM/PAM for amino acids, encoding evolutionary and structural relationships between monosaccharides and linkages. BioPython's `PairwiseAligner` supports custom substitution matrices but has never been exposed in any glycan-specific web application. | GlycanBench implements global Needleman-Wunsch alignment (BioPython `PairwiseAligner`, mode=`global`) using **GLYSUM.xlsx** as the default substitution matrix — the only glycan-native scoring scheme in the published literature. IUPAC strings are tokenized into alternating [monosaccharide, linkage] arrays; `difflib.get_close_matches` (cutoff 0.85) maps near-exact names to the vocabulary rather than hard-failing; unknown sugars → `UNK1`, unknown linkages → `UNK2` (both with zero substitution score). Affine gap penalties (configurable open + extend) apply in both modes. Users may switch between GLYSUM and **custom match/mismatch/gap scoring** via radio buttons, with greyed-out score fields when GLYSUM is active. Output: token-padded columnar alignment display (all tokens padded to uniform width, pipe `|` for identity), alignment score, and percent identity observation string. TXT export is available. This is the only web-accessible glycan sequence aligner implementing GLYSUM with per-token fuzzy name resolution and dual scoring modes. |

## CLUSTER

All three cluster tools use the same backend endpoint (`POST /api/cluster/run`) with the `mode` parameter (`standard`, `optimal_k`, `outliers`) and `clustering_method` (`agglomerative`, `kmeans`) controlling behavior. All three share an identical UI pattern: a glycan name+IUPAC input table with add/remove rows, magic-fill defaults, and an advanced options collapsible panel (fingerprint type, radius, n_bits, linkage method, distance metric). The `iupac` string is now preserved through the normalization pipeline alongside the derived SMILES, enabling glycan-native distance metrics that require the original symbolic sequence.

| Tool | State of the Art | Our Contribution |
|------|-----------------|-----------------|
| **Cluster Three or More Glycans** (`/cluster/multiple`) | Glycan clustering has been performed using tree edit distance (O(n²), computationally expensive), `glycowork` graph similarity, and SMILES-fingerprint Tanimoto distance with agglomerative clustering. SciPy `linkage`/`fcluster` is the standard implementation. Seaborn heatmaps are standard for pairwise distance visualization. No web tool provides interactive agglomerative glycan clustering with both fingerprint-based and glycan-native graph-similarity metrics selectable at runtime. | IUPAC strings are batch-converted to SMILES via `glycowork.motif.processing.IUPAC_to_SMILES()` or accepted directly, with the original IUPAC string retained for glycan-native distance computation. Users select: **clustering method** (Agglomerative with distance threshold slider, or K-means with k slider); **fingerprint type** (Morgan, Atom Pair, Topological Torsion, RDKit); **radius** (2 or 3); **n_bits** (1024 or 2048); **linkage method** (average/UPGMA, single, complete, ward — ward auto-forces Euclidean metric); **distance metric** — Tanimoto, Dice, Cosine, Euclidean (all fingerprint-based), or **`glycowork` graph similarity** (`glycowork.motif.graph.compare_glycans()`, bypasses fingerprints entirely, uses the original IUPAC strings directly). The `glycowork_similarity_available` flag in the response signals to the frontend whether this metric can be offered. Outputs: Matplotlib dendrogram (agglomerative only), Seaborn pairwise heatmap, cluster membership dict, PNG download, and CSV of cluster assignments. K-means uses `sklearn.cluster.KMeans` (n_init=10, max_iter=300, random_state=42) on the raw fingerprint bit matrix. The addition of a glycan-native graph-similarity metric alongside the full suite of cheminformatics fingerprints, switchable at runtime without code changes, is unique to GlycanBench. |
| **Optimize Number of Clusters** (`/cluster/optimize`) | Determining the optimal number of clusters for glycan data has no established dedicated tool. Elbow plots (inertia vs. k) and silhouette analysis are standard in general cheminformatics. For hierarchical clustering, sweep plots of cluster count vs. distance threshold are used ad hoc in research code but not exposed interactively for glycan data. | GlycanBench runs `mode=optimal_k`: agglomerative clustering is executed at each threshold in a user-configurable list (default: 0.1, 0.2, …, 0.7 in steps of 0.1), recording cluster count at each threshold. The glycowork graph metric is available here as well. Outputs: a Matplotlib line plot of cluster count vs. threshold (the "elbow plot"), a numeric threshold-curve table rendered in the UI, the cluster dendrogram for the chosen starting threshold, and the pairwise distance heatmap. All images are PNG-downloadable. This interactive, glycan-specific threshold-sweep visualization does not exist in any current glycomics tool. |
| **Detect Outlier Glycans** (`/cluster/outliers`) | Outlier detection in glycan sets has been performed manually by dendrogram inspection. No automated, web-accessible tool reports singleton clusters with quantitative outlier severity for glycan data. | GlycanBench runs `mode=outliers`: after agglomerative or k-means clustering, any glycan forming a singleton cluster (size = 1) is flagged as a potential outlier. For each singleton, mean pairwise distance to all other glycans is computed from the full distance matrix as a severity score (works with any metric including the glycowork graph similarity). The UI renders outliers in a red-highlighted list with cluster ID and mean distance. Singletons with mean distance > 0.45 receive an additional "STRONG OUTLIER" badge. A green "no outliers detected" message is shown when all clusters have size ≥ 2. The dendrogram and heatmap are also returned to visually confirm outlier separation. This is the first automated, quantitative glycan outlier detection tool accessible without programming. |

## PREDICT

| Tool | State of the Art | Our Contribution |
|------|-----------------|-----------------|
| **Immunogenicity** (`/prediction`) | Glycan immunogenicity prediction is an emerging area. GlyNet and related GNN approaches (Bojar et al., 2021, *Cell Chemical Biology*) use graph representations with GIN or GAT architectures. `glycowork` provides LSTM and GNN classifiers for glycan property prediction. The field consensus is that graph-based representations capturing branched topology outperform linear sequence models. Known xenoantigens (AlphaGal = Gal(α1-3)Gal, Neu5Gc) are well-established. No web-accessible immunogenicity predictor for arbitrary glycan sequences currently exists in the public domain. | GlycanBench deploys a **glycoword-graph MPNN** classifier. The representation pipeline: IUPAC → regex normalization (unusual bond notation) → tokenization into alternating [sugar, linkage] tokens → unknown-token masking (`UNK_SUG`, `UNK_BOND`) → **glycoword** extraction (5-token pentamer windows, step 2: sugar–bond–sugar–bond–sugar, analogous to k-mers) → vocabulary lookup in `glycoword_vocab.json` → graph construction (nodes = glycoword indices, forward+reverse sequential edges) → `torch_geometric Data`. **MPNNClassifier architecture**: `nn.Embedding(|vocab|+1, 64)` → 2× `MPNNLayer` (additive `MessagePassing`, `BatchNorm1d`) → `global_mean_pool` → MLP `64→32→1` → sigmoid → threshold 0.5. Unknown token embedding initialized to mean of all known embeddings at inference. Three alternative architectures (GINClassifier, GATClassifier, LSTMClassifier) are trained and stored but not served in the active API; MPNN is the deployed model. Rule-based motif flags run in parallel for AlphaGal (Gal-α1-3-Gal xenoantigen), NonHumanSialicAcid (Neu5Gc), and ComplexNGlycan core. The frontend presents: an animated probability bar; Immunogenic/Non-Immunogenic classification with score; a confidence badge (high/medium/low derived from `max(score, 1-score)`); detected motif cards with descriptions; vocabulary analysis reporting unknown sugar/bond/glycoword counts; tokenization visualization (each IUPAC fragment displayed as a badge); download as JSON. **Acknowledged limitation**: the graph encodes a linear token chain rather than the branched tree topology of the glycan — branching is encoded implicitly through the glycoword vocabulary rather than explicitly in the graph edges, which limits structural expressivity relative to true tree-GNNs. |

## CHAT

| Tool | State of the Art | Our Contribution |
|------|-----------------|-----------------|
| **Chat** (`/GlycomicsChat`) | General-purpose LLMs (GPT-4, Claude, Gemini) have broad scientific knowledge but no glycomics specialization, no live database access, and no domain enforcement. Domain-specific chatbots using RAG over glycomics literature exist in research settings but are not publicly accessible and do not integrate live tool calls. LangChain ReAct agents are state of the art for LLM + external tool integration. No publicly available glycomics chatbot combines a domain-enforced LLM with simultaneous live PubMed, ArXiv, and GlyTouCan database access and a structured expert persona. | GlycanBench deploys a Groq-hosted `openai/gpt-oss-120b` (temperature=0.1, top_p=0.9, max_tokens=2048) behind a ~200-line glycomics system prompt defining the model as a "Glycan Discovery Engine." Domain gating is strict: non-glycomics queries receive a canned refusal. **External tools** (user-selectable via category toggles in the UI): **Literature** — PubMed via LangChain `PubmedQueryRun`; ArXiv via `ArxivAPIWrapper` (top_k=5); **Databases** — GlyTouCan REST API (auto-triggered when regex `G\d{5}[A-Z]{2}` matches the input, fetching WURCS, IUPAC, mass, formula); structure analysis and synthesis pathway reasoning handled in-prompt. **Intelligent tool selection**: when a category is selected, `intelligent_tool_selection()` now uses an **LLM-based router** — a compact JSON-returning routing prompt sent to the same Groq model asks which specific tools are genuinely useful for the query. The parsed result overrides individual tool flags, with guaranteed fallbacks (PubMed for Literature, Structure Analysis for Databases) if no tool is selected by the router. A keyword-scoring heuristic (`_keyword_route_tools`) is preserved as an automatic fallback when the LLM routing call fails. **Question-type analysis** (`analyze_question_type`) categorizes the query (mechanistic / structural / functional / current research / methodological / clinical / biosynthetic) and injects the category as context into the prompt. **Confidence scoring** (`calculate_response_confidence`) evaluates response length, scientific term density, glycan-specific notation presence, quantitative content, external evidence used, and uncertainty acknowledgment. The frontend renders tool-used badges, confidence badges, processing time badges, and — when a GlyTouCan accession is resolved — structured panels for WURCS, IUPAC, GlycoCT, mass, and molecular formula. The combination of strict glycomics domain enforcement, LLM-driven tool routing with keyword fallback, live multi-source retrieval, question-type-aware prompt augmentation, and a fully typed React chat interface is not available in any existing tool. |
